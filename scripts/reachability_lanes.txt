# Lane -> client entry symbol, for scripts/check_reachability.py
# scar:mechanism-shipped-inert-2026-09-10
#
# One record per blank-line-separated block. Five REQUIRED fields, all non-empty:
#
#   lane         a short id for the lane. Repeated across records when a lane has
#                several client entry points (open / pay / settle).
#   symbol       the FULLY QUALIFIED symbol as `go tool nm` prints it:
#                  github.com/nerolabs/silt/core/node.(*Node).SubmitRelayPay
#                A bare identifier is refused. A bare identifier is what the grep
#                sweep keyed on, and it is why an inert method hid behind a live
#                namesake (demand.Commit) and never showed up in the count.
#   label        a substring that occurs EXACTLY ONCE in docs/release-checklist.md,
#                inside the lane's posture line. The gate reads the enclosing bullet
#                or paragraph and asks whether it says the lane CANNOT BE EXERCISED.
#   claim        the public claim in the release checklist this lane backs. This is
#                why the lane is in a BOUNDED gate at all.
#   substantial  why this symbol cannot be inlined away, so that its ABSENCE from the
#                symbol table is proof and not noise.
#
# WHAT `substantial` MUST BE ABLE TO SAY, AND WHY THE GATE RE-CHECKS IT
#   Never name a one-line wrapper. adapters/relay.DialThroughPaid's whole body is
#   `return dialThrough(...)`; the compiler inlines it into its caller and the symbol
#   vanishes from a binary where the lane is perfectly live. Name a symbol the
#   COMPILER refuses to inline — and say so with the compiler's own number, which
#   `go build -gcflags=-m=2 <pkg>` prints as `cannot inline <name>: function too
#   complex: cost N exceeds budget 80`. The gate runs that measurement itself, per
#   lane package, and REFUSES a record whose symbol draws `can inline` instead.
#
#   That verdict replaced two source-shaped proxies on 2026-09-11, each retired by a
#   measurement rather than by preference:
#     - "the body carries a CALLBACK CLOSURE, which surfaces as `<symbol>.funcN`".
#       A closure is a property of a client entry point handing work to a transport.
#       Consensus validators do not have one: run the retired rule against the nine
#       freeze-manifest records below and it refuses SEVEN of them — setD3Digests,
#       validateD3Digests, CheckConsensusParams, genesis.Build, printEraObservable,
#       StartupEraLines and chainstore.Recover — every one a symbol the compiler will
#       not inline at any call site.
#     - the `.funcN` row as a PRESENT-path anti-hollowing witness. A closure can be
#       inlined into its own parent, leaving no `.funcN` row in a binary where the
#       parent is plainly live, so the witness reported a live mechanism as hollowed.
#
#   NEITHER TEST DOMINATES THE OTHER, AND THE GAP IS NAMED. The inline verdict is not
#   strictly stronger than the `.funcN` witness. Gut `core/chain.v5ValidateSlashes` —
#   delete the SlashesBytesCap check, the M2 era floor and the culprit walk, keep one
#   used closure — and the compiler still says `cannot inline` at cost 263, so THIS GATE
#   RUNS GREEN while the retired witness goes RED on the same binary. The reverse case
#   is `stateRootLeavesV5`, live and load-bearing, which the retired witness called
#   hollowed. Both are the same compiler event read two ways. The trade is right — the
#   inline verdict catches the hollowing that actually happens and drops a false RED —
#   but a green run of this gate is NOT evidence that a lane's mechanism is intact.
#   scripts/check_reachability.py carries the full two-way table.
#
# AN UNREASONED ROW FAILS. `claim` and `substantial` are checked for length and for
# null-words, and each has a mechanical companion: `label` must resolve in the
# checklist, and the compiler's inline verdict must agree with `substantial`. An
# allowlist rationale is itself a claim, and it decays exactly like a cited test name.
#
# ADDING A LANE IS ADDING A RECORD. Keep the set bounded to lanes the release
# checklist makes a public claim about. This is not a sweep of exported symbols: the
# floor-box keystone is inert by ratified owner direction (D-RECOMPUTE-FREEZE) and
# would drown the signal.
#
# ⚠ REACHABILITY IS NECESSARY AND NEVER SUFFICIENT. A green run proves every symbol
# below survived linking. It proves nothing about whether any mechanism is correct,
# or whether it computes what its record claims. DO NOT BOOK A FREEZE-MANIFEST ITEM
# AS BUILT ON THE STRENGTH OF A GREEN REACHABILITY RUN.

# ---------------------------------------------------------------------------
# The paid delivery lane — RC-open, graded at E5. Three client entry points:
# open, top-up, settle. Two are linked; the top-up is not.
#
# THE TWO HALVES ANCHOR ON SEPARATE POSTURE LINES, AND THEY HAVE TO. A block is
# classified as a WHOLE: it says "cannot be exercised", or it says the lane has
# not yet been exercised, and one that says both states no posture and FAILS. The
# open/settle halves are linked and unrun in the field; the top-up half is not in
# the binary at all. Those are the two postures, so pointing both at one label
# would force the honest text to drop one of the two facts — or to reword around
# the phrase list, which is defeating this gate with a thesaurus. Two labels, two
# blocks, each classified on its own.
#
# An anchor never contains the reserved phrase or the symbol's own name. If it
# did, resolving the anchor would satisfy the assertion by itself and both halves
# of the pair would go unchecked.
# ---------------------------------------------------------------------------

# THE ERA-4/V5 FREEZE-MANIFEST MECHANISMS
#
# Why they are in a file whose header says "lanes the release checklist makes a
# public claim about": the checklist now makes one about them, under "Every
# era-4/v5 freeze-manifest mechanism is in the shipped binary". They were added
# because the gate built after owner call F shipped INERT did not watch the class
# of surface F was. `CheckConsensusParams` sat with zero non-test callers for a day
# while `D-CFGBIND-BUILT-2026-09-10` read "✅ BUILT … Closes R-CONSENSUS-CONFIG-UNBOUND
# on the production path", and a green run of this gate would have said nothing.
#
# THE MAPPING, NOT A SAMPLE. The manifest holds 22 items. SIX name a mechanism that
# lives in production Go — items 1, 3, 6, 10, 19 and 20 — and all six are below, as
# NINE records (items 3, 19 and 20 each have two independently droppable halves).
# The other sixteen have nothing for this gate to hold: 2, 4, 5, 12 and 13 are
# dropped or refuted, 8 is declined for the RC, 7, 9, 16, 18, 21 and 22 are owed, and
# 11, 14, 15 and 17 are delivered as TESTS — a test symbol is never in ./cmd/silt,
# and a test that can see a symbol is itself the caller keeping it alive.
#
# ITEM 18 IS EXCLUDED ON A NARROWER GROUND THAN THE OTHER FIVE OWED ITEMS, AND THE
# DIFFERENCE MATTERS. Items 7, 9, 16, 21 and 22 have no symbol in the tree. Item 18
# does: `core/statehash.IngestBlockWitnesses` is the R3 witness-bound gate, the
# compiler prices it at 478 against a budget of 80, and it is ABSENT from the linked
# ./cmd/silt because it has zero non-test callers. What is owed is the item's
# DELIVERABLE — a gob message-length pre-check inside it — not the function. So item
# 18 is out of this gate because its deliverable does not exist, NOT because its
# surface is missing, and the surface being unlinked is a separate live finding:
# `R-INGEST-WITNESSES-INERT` in ROADMAP.md. Wiring it up is a consensus-surface
# change and is not a thing this file may do to make a run green.
#
# ⚠ REACHABILITY IS NECESSARY AND NEVER SUFFICIENT. DO NOT BOOK A MANIFEST ITEM AS
# BUILT ON THE STRENGTH OF A GREEN REACHABILITY RUN. A green run proves the symbol
# survived linking. It proves nothing about whether the mechanism is correct, or
# whether it computes what its record claims. Item 20 is the standing example: two of
# its three arms are below, the third has no mechanism in the tree, and this file
# cannot tell the difference between "the third arm is owed" and "the item is done".
#
# ADDING A MANIFEST ITEM HERE MEANS ADDING A RECORD AND A CHECKLIST BULLET. An item
# whose mechanism is owed gets neither: there is no symbol to name, and inventing a
# posture line for a mechanism that does not exist is the over-claim this gate
# refuses in the other direction.
# ===========================================================================

lane: freeze-era-observable
symbol: github.com/nerolabs/silt/core/chain.StartupEraLines
label: the era pair an operator reads at start-up
claim: The daemon half of item 19. A chain carrying no v5 block is a healthy dark network under an era-4 build and the WRONG BUILD under an era-2 one, and neither number discriminates alone, so the item's claim is that both print together on the boot path. This is the reducer that composes them, and cmd/silt/daemon.go's eraStartupLines wrapper is its only production caller, so it leaves ./cmd/silt exactly when the boot path stops printing the pair.
substantial: Cost 906 against an inline budget of 80, `cannot inline StartupEraLines` — the second-widest margin in this file. THIS RECORD USED TO NAME THE WRAPPER, cmd/silt.eraStartupLines, and that was an arithmetic accident waiting to fire: the wrapper is ONE body line whose cost of 120 is two non-inlinable call charges (Go prices a call to a non-inlinable callee at about 57), not body substance. Fold those two calls into one — pass the EraState in, or let StartupEraLines take the chain — and the wrapper drops under budget, this gate REFUSES the record, and CI goes red on a refactor that changed nothing about reachability. Naming the reducer removes the accident at no cost to the signal: deleting the boot-path call drops BOTH main.eraStartupLines and core/chain.StartupEraLines from the binary.
