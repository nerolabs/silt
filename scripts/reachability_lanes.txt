# Lane -> client entry symbol, for scripts/check_reachability.py
# scar:mechanism-shipped-inert-2026-09-10
#
# One record per blank-line-separated block. Five REQUIRED fields, all non-empty:
#
#   lane         a short id for the lane. Repeated across records when a lane has
#                several client entry points (open / pay / settle).
#   symbol       the FULLY QUALIFIED symbol as `go tool nm` prints it:
#                  github.com/nerolabs/silt/core/node.(*Node).SubmitRelayPay
#                A bare identifier is refused. A bare identifier is what the grep
#                sweep keyed on, and it is why an inert method hid behind a live
#                namesake (demand.Commit) and never showed up in the count.
#   label        a substring that occurs EXACTLY ONCE in docs/release-checklist.md,
#                inside the lane's posture line. The gate reads the enclosing bullet
#                or paragraph and asks whether it says the lane CANNOT BE EXERCISED.
#   claim        the public claim in the release checklist this lane backs. This is
#                why the lane is in a BOUNDED gate at all.
#   substantial  why this symbol cannot be inlined away, so that its ABSENCE from the
#                symbol table is proof and not noise.
#
# WHAT `substantial` MUST BE ABLE TO SAY, AND WHY THE GATE RE-CHECKS IT
#   Never name a one-line wrapper. adapters/relay.DialThroughPaid's whole body is
#   `return dialThrough(...)`; the compiler inlines it into its caller and the symbol
#   vanishes from a binary where the lane is perfectly live. Name the substantial
#   entry point — one whose body carries a CALLBACK CLOSURE, which surfaces as
#   `<symbol>.funcN` in the table. The gate measures the declaration and REFUSES a
#   thin entry rather than passing it.
#
# AN UNREASONED ROW FAILS. `claim` and `substantial` are checked for length and for
# null-words, and each has a mechanical companion: `label` must resolve in the
# checklist, and the body measurement must agree with `substantial`. An allowlist
# rationale is itself a claim, and it decays exactly like a cited test name.
#
# ADDING A LANE IS ADDING A RECORD. Keep the set bounded to lanes the release
# checklist makes a public claim about. This is not a sweep of exported symbols: the
# floor-box keystone is inert by ratified owner direction (D-RECOMPUTE-FREEZE) and
# would drown the signal.

# The paid delivery lane — RC-open, graded at E5. Three client entry points:
# open, top-up, settle. Two are linked; the top-up is not.
# ---------------------------------------------------------------------------

lane: paid-delivery
symbol: github.com/nerolabs/silt/core/node.(*Node).OpenDeliverySessionRemote
label: Open at the RC: the paid delivery
claim: The checklist declares the paid delivery lane open at the RC and graded at E5; a fetcher that cannot open a session cannot produce any C2 number at all, so this symbol is the lane's first load-bearing claim.
substantial: Signs the open, marshals it and hands n.request a callback closure that decodes the handle and the commitment; the closure surfaces as OpenDeliverySessionRemote.func1, so this symbol is far past the inliner's budget and its absence would be real.

lane: paid-delivery
symbol: github.com/nerolabs/silt/core/node.(*Node).SubmitDeliverySettle
label: Open at the RC: the paid delivery
claim: The C2 numbers the checklist calls sim-driven are settlement numbers; this is the fetcher half that signs the cumulative count and submits it, so the lane's economic claim rests on this symbol being in the binary.
substantial: Signs a cumulative receipt and passes n.request a closure that reads the settled credits off the response; the closure surfaces as SubmitDeliverySettle.func1, so an absence here is a dropped symbol, never an inline.

lane: paid-delivery-topup
symbol: github.com/nerolabs/silt/core/node.(*Node).FundDeliverySessionRemote
label: Open at the RC: the paid delivery
claim: The checklist claims a paid delivery lane whose sessions are budgeted; top-up is how a session's budget rises after admission, so the RC posture line has to say whether an operator can do it. It cannot: this symbol has zero non-test callers and the linker drops it.
substantial: Signs a SessionFund, marshals it and passes n.request a closure that reads the post-top-up budget; the closure surfaces as FundDeliverySessionRemote.func1, so its absence from the table is the linker dropping it, not an inline.
