## 1. The mechanism, in one paragraph

An honest validator is slashed and permanently evicted **because** `VerifyEquivocation` quantifies
over a fact (the height the two signatures were released at) that is not inside the message the
culprit signed, and reads it from a struct field the accuser controls (`equivocation.go:50`), while
the verified message comes from `Hash()` (`:53`), which short-circuits to the accuser-supplied
`b.Pruned` (`chain.go:658-660`). Two genuine signatures at two different heights, re-labelled with
one shared height, verify as a double-sign; `Append` commits the slash. This change addresses that
**by recomputing the evidence hash from the block body, bypassing both `Pruned` and the memo**, so
the declared height is the signed height or the pair is refused (`ErrPrunedEvidence`). Evidence:
RT-SV-1/1b through `Append`; the gates below are those probes inverted.

## 2. The options weighed (the cert did this; recorded here so the choice travels with the code)

| Option | Cost | Benefit | Call |
|---|---|---|---|
| (a) recompute from body, refuse pruned evidence | a pruned double-sign is unslashable (R-LATE-REVEAL) | the only rule that closes already-minted signatures; strictly narrowing, cannot manufacture a slash; the rule the type's own doc already states | **TAKE** |
| (b) bind height into the signature domain | new domain; era-1 `signedBlock` untouched; cannot rebind minted history | none over (a) | REFUTED |
| (c) carry headers, verify by recompute | an unbound header is the same free field one level down | none | REFUTED as posed |
| (d-2) `Slashes` encoded-BYTE ceiling | a liveness bound on how much evidence one block carries | (a) forces full bodies into a slot `Prune()` never reaches; without the cap (a) trades I5 for an immutable-#8 break | **TAKE, required** |
| (d-3) two-level hash (`AnswerDigest`) at the next `BlockVersion` | a format change | prunable-yet-verifiable evidence for future history | DEFER to the next mint |

## 3. The shapes that are the Builder's

1. **Where the rule lives:** in `VerifyEquivocation`, not `validateSlashes` — `FindEquivocations`
   gates on it, so proposer and validator close in one edit (no doomed-proposal loop).
2. **One hash function, three sites:** the candidate comparison at `equivocation.go:130` and the
   verification use the same body-recompute helper, which bypasses `hashMemo` (G-4, G-6).
3. **The cap is a validity rule of class immutable-#8 resource ceiling** (like the carrier byte
   ceiling), **not** RegCap's class and **not** a security parameter: raising it never admits a forged
   slash; lowering it never convicts an honest validator. Named constant, named error, at-ceiling
   accepted (the I4 liveness edge). The VALUE is measurement-gated (G-3) and the owner ratifies it
   on immutable-#8 grounds; the transport frame (132 MiB) is the ceiling the value cannot exceed.
4. **No era gate, no grandfather** unless G-1 (the persisted-chain scan) finds a committed slash
   with pruned evidence. G-1 passing ⇒ the practical fork set is empty.
5. **Canon edits ride in the same PR:** `retention.go:17-19`, `chain.go:691-697`, `chain.go:653-657`,
   the I5 scar in `docs/design/consensus-invariants.md`, a `docs/decisions.md` entry.
6. **Not built on this cert:** R-RELOAD-RE-VERIFY (own-disk skip), R-BOX (the floor box's
   un-verified `b.Slashes` read; Boulder 1's front).

## 4. The gates and their ablations

T-1/T-2 (era-1 / era-2 forgery through `Append`) are RED on main and go green-as-attack again if the
recompute is removed. T-3 (a genuine double-sign still convicts) guards against fix-by-refusing-
everything. T-4 supersedes `TestQ2_PrunedBlockStillSlashable`, which pinned the behaviour being
removed. T-5 reproduces and gates the honest-node delivery vector (§8.1 of the cert: a Byzantine PEER
makes an honest node queue the forgery). T-6 the byte ceiling, over and at. The I5 model-check gains
three axes (declared-vs-signed height; `Pruned` ∈ {unset, real, forged}; era ∈ {1, 2}).

## 5. As built (2026-09-03)

- Rule in `CheckEquivocation` (named-error form; `VerifyEquivocation` wraps it); `bodyHash` is the
  one function for verification and `FindEquivocations` candidate selection; `Hash()` memoizes it.
- `SlashesBytesCap = 16 MiB` provisional, checked first in `validateSlashes`, every era; the proposer
  packs `pendingSlashes` under it (always at least one, arrival order, rest carried).
- G-3 measured: one reg-laden proof (two ~1.5 MB `Answer` bodies) = 3.00 MiB; 5 fill the cap; 15.0 MiB
  resident after decode; `validateSlashes` 11.5 ms. **Owner ratifies the value.**
- Controlled revert (recompute removed, `Pruned` trusted): T-1, T-2, T-4, G-4 and both §9 sweeps RED.
- The Tester's stricter reading (any `IsPruned()` ⇒ refuse) was adopted: it is the cert's own T-4 text,
  and `PruneBelowHorizon` never prunes a reg-free block, so the literal "recompute-and-compare" form
  admits nothing the stricter form refuses on any honest path.
- Cost note: `FindEquivocations` now body-hashes both sides per FORK block (the peer's suffix above our
  finalized head), bounded by the reconcile's own validation work; never per chain block.
- Not built (by the cert): R-RELOAD-RE-VERIFY, R-BOX. The Builder seat was unavailable (API overload,
  twice); the planner built in-session under the same brief.
