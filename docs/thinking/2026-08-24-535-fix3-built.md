# #535 fix (3) built — the WS liveness-floor escape, per the ratified design

**Date:** 2026-08-24. **Issue:** #535. **Status:** BUILT, model-checked. The
design was ratified in `2026-08-24-535-fix3-design.md` (PR #544); this doc
records the build against its checklist and the deviations, per the
pace-before-code discipline (the deliberation happened in the design doc — this
is the execution record).

## What shipped

- `Config.LivenessRecoveryHeight` (0 = off): the operator-directed epoch
  boundary at which mature-epoch validation re-bases against the live
  qualified bonded set. Consensus-coordination config, WSCheckpoint trust
  class.
- `effectiveEpochSet(h)`: the single governing-set function. Returns the live
  qualified set at `h == LivenessRecoveryHeight` when h is a boundary, else the
  frozen `epochSet`. All three validation predicates consult it —
  `attesterQualifiedAt`, `proposerQualifiedAt`, `requireEpochWeightQuorum` — so
  the set a quorum is sized over and the set it is filled from can never differ
  (the #402 law). It shares `liveQualifiedSet()` with `rotateEpoch`, so the
  recovered boundary's governing set is byte-identical to the snapshot its own
  commit freezes.
- Height threading: `ValidateProposal`, `collectQuorumSigs`, and
  `requireQuorumStack` pass `b.Height`; `SupportMeetsQuorum` now takes the
  gather height explicitly (both node call sites had it in hand). Every other
  height reads the frozen set unchanged; `rotateEpoch` is unchanged.
- Operator surface: `-liveness-recovery-height` daemon flag (WS caveat in the
  help text; refuses a non-boundary value; loud ARMED banner),
  `Chain.BoundaryLivenessFloorLost(h)` (the evidence-based wedge predicate: the
  frozen members still live-bonded carry ≤ ⅔ of frozen weight), a
  `stalled-at-boundary` WARN in the round-change path, and a `chain-status`
  next-height-is-a-boundary diagnosis line.
- Model-check: `core/chain/modelcheck_535_fix3_recovery_test.go` — the four
  design properties. Recovery-when-invoked (the wedge topology commits at the
  directed boundary and the chain resumes on the rotated lighter set), safe
  default (LRH=0 and LRH=wrong-boundary both stall with `ErrNoQuorumWeight`;
  a non-boundary LRH never fires), determinism (a replica replaying the same
  blocks with the same directive reaches the identical head), and the
  documented non-provable residual (the operator's judgment — the WS trust).

## The RED proof (failing-first, the #432 pattern)

The oracle needs the new API surface to compile, so failing-first is proven
against a recorded revert, exactly as the #432 S1/S2 oracles were: with
`effectiveEpochSet` reverted to `return c.epochSet` (the shipped pre-fix rule),
`TestModelCheck_535_Fix3_RecoveryAtDirectedBoundary` FAILS at the recovery
assertion and `TestModelCheck_535_Fix3_SafeDefaultStalls` still PASSES (it pins
the stall the pre-fix rule already had). Mechanism restored → both GREEN.

## Deviations from the design checklist (all additive)

1. **`SupportMeetsQuorum` takes the height as an explicit parameter** rather
   than a wrapper — the compiler then found every call site, and the gather and
   validation provably judge the same governing set.
2. **The gather's solicitation filter is also threaded**
   (`AttesterEligibleAt`, used by `maybeProposeBondDrain` and
   `proposeAtNewView`): a live-but-unfrozen member's weight is in the recovery
   denominator, so a frozen-set solicitation filter could leave the assembled
   coalition short of the very bar it is measured against. The model-check's
   fresh-joiner case is the chain-level face of this.
3. **Proposer-side probes stay frozen** (`ProposerEligible`,
   `EligibleProposers`, the designee rotation): the designee schedule must be
   identical on every replica, the frozen set gives that, and recovery does not
   need a non-frozen proposer — a live frozen member proposes the boundary and
   `proposerQualifiedAt` governs validation. Not a gap: the re-based membership
   still fills the quorum via attestations.
4. **`chain-status` takes `-epoch-blocks`** (default `DerivedEpochBlocks`) for
   its diagnosis: the command reads a config-less `chain.cbor` snapshot, so it
   cannot compute live weight or "not advancing" — it names the state and points
   at the daemon's `stalled-at-boundary` WARN, which carries the weight evidence
   (`BoundaryLivenessFloorLost`). The design's exact diagnosis line lives in the
   daemon log, where the evidence is.

## I1–I5 (the consensus-touching-PR statement)

- **I1 (touched):** at the one directed boundary, both size-set and
  membership-set are `effectiveEpochSet(H)` — any two >⅔ coalitions of the H
  block overlap in >⅓ of the SAME total, so intersection holds *within the
  re-based set*. The residual — the re-based set excluding possibly-honest
  lapsed weight raises the Byzantine fraction (the fix (2) refutation) — is
  exactly what the operator vouches against by invoking recovery: the
  documented, off-by-default WS trust, identical to accepting a WSCheckpoint.
  Never automatic; a bled boundary stalls by default (the fix (2) model-check
  still pins that).
- **I2 (untouched):** signing/watermark rules unchanged.
- **I3 (touched, preserved):** the set still changes only at a finalized
  boundary — the re-base IS at a boundary, fires for that one height, and the
  next epoch is frozen by the normal `rotateEpoch` from the same
  `liveQualifiedSet`. A non-boundary directive never fires (pinned by test).
  Admission stays weight-based.
- **I4 (touched, this is the point):** the recovery restores boundary liveness
  for a genuine >⅓ loss under an explicit human directive; without it the
  stall remains (certified-correct). Operator visibility added (S5): the wedge
  state is named in the daemon log and chain-status, never silent.
- **I5 (untouched):** fork-choice and slashing unchanged; fork-choice weights
  still read the frozen snapshot.

## Residuals (owned)

- A wrongly-invoked recovery (loss is actually a partition/attack) can fork —
  the fix (2) counterexample. Accepted WS residual, carried in the config
  comment, the flag help text, and the certification.
- Operators must set the SAME height — social coordination, not protocol.
- A mid-epoch wedge (>⅓ frozen weight lost with the head short of the
  boundary) is NOT covered by fix (3), which re-bases a boundary block only —
  the interim floor (coordinated WSCheckpoint restart) remains the recovery
  there, unchanged from the certification.
