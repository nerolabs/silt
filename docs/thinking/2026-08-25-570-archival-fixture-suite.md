# #570 — archival-format golden fixtures: the build record

**Date:** 2026-08-25. **Trigger:** owner question "do we need a test suite for the
archival format — later or now?" Answer recorded on issue #570: split the question.
The *compatibility* half ships now as a gap filler while the DEEP re-run executes;
the *tier* half (snapshots, bootstrap-from-archive, omission proofs) stays
research-gated behind the D-TIERING state-root consult.

## What shipped

`core/chain/archival_fixture_570_test.go` + four committed fixtures in
`core/chain/testdata/archival/` (era-1, era-2, era-2-pruned, mixed era-1→era-2 —
the last being the real field-store shape since the #432 era flip). Each fixture is
the exact `EncodeBlocks` representation `chainstore.Save` persists. The replay test
reads only the committed bytes, `Reload`s them at HEAD, and asserts pinned
constants: block count, head hash, and derived-state spot checks (bonded set,
revocation/unrevocation status).

## The property and the discipline

The property: **bytes written by an older binary must replay at today's HEAD.**
No other test asserts it — everything else mints fixtures at HEAD with HEAD's code,
which is exactly why #558 (era-2 replay always failing → silent genesis fallback)
lived from #432 to 2026-08-25.

Write-once: a fixture is never regenerated; a failure is fixed in the
validation/decode path, never in the fixture. A new era ADDS a fixture — era-3
(the D-TIERING state root) must add one, making this suite the standing RED home
the state-root consult's Q5 asks for. The generator refuses to overwrite.

## RED proof

Reinstating the #558 bug (verifyAtt's era-2 arm reverted to bare-hash verification)
fails era-2, era-2-pruned, and mixed at block 1 with `bad signature`, while era-1
stays green (its form was never broken). Restored, all green. The head-hash pins
additionally catch any change to hash computation over committed bytes (a silent
hard fork) — the class the #563 pooled-buffer change would have risked without its
identity test.

## Scope honesty

This guards decode + validation + hash identity over committed histories. It does
NOT cover: chainstore file-level crash-safety beyond the existing atomic-rename
tests, cross-BINARY generation (fixtures are generated by HEAD once, then frozen —
the freeze is what makes them "older binary" bytes for every future HEAD), or the
archival tier's serving behavior (research-gated).
