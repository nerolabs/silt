## The mechanism this task addresses (attribution)

The R1.4 recompute-soundness cert established that every untrusted witness value/predicate is
`Resolve`-anchored against `prevStateRoot`, and it shipped 10 driven adversarial-committed-root
FIX gates + 1 class-M cross-class gate. But two coverage holes remain, both named by R1.4:

1. **The coverage reflection walks only 3 of the 4 value/predicate carriers.** `r12Carriers()`
   reflects `StateRootAttScreen` / `StateRootRotateMember` / `StateRootBondRegScreen` (24 fields)
   but NOT `StateRootRotateScalar` (the 8 activation/latch scalar OldValue/Proof pairs). Design
   §4's "23 obligations" enumeration explicitly includes those 8 scalar uses as `already-anchored`
   (fold OldValue vs prevStateRoot). They are hand-verified in the cert, not reflection-pinned.
   A new value-bearing field on the scalar carrier escapes the walk. (R1.4 residual
   R-CARRIER-REFLECTION.)

2. **The "already-anchored" fields have no DRIVEN teeth.** The 10 FIX fields each redden when
   their `Resolve` anchor is dropped (proved by the existing gates). The already-anchored fields
   (the proofs, the fold OldValues, the scalar pairs) are classified by reason, but nothing drives
   them: if their fold/Resolve anchor were dropped, no probe reddens. The task requires a probe
   for EACH of the 23 predicate/value obligations that goes RED on anchor ablation.

The fix is test-only (no source change to the box). It ADDS a per-field oracle-probe layer that
turns the hand-verified coverage of R1.4 into reflection-pinned, ablation-driven coverage.

## Why the already-anchored fields need a probe (not just a classification)

R1.4's classification says "EpochSetProof is anchored by the fold." That is TRUE but UN-DRIVEN:
delete the fold's OldValue-vs-prevStateRoot verification and nothing in the current suite reddens
on the EpochSetProof/OldValue row. The oracle-probe for each of these forges the field's committed
input, folds an attacker-committed root, and asserts the box STALLS — then the teeth-proof drops
the anchor (the fold's prevStateRoot check, or the Resolve of the proof-bearing field) and confirms
the probe goes RED (wrong-accept). This is the same "leave-one-out proves load-bearing" discipline
as the snapshot oracle (`TestLeaveOneOutProvesEachFieldLoadBearing`).

## probeUncovered — name A1/A2/A3 explicitly (task item 2)

`probeUncovered` (`modelcheck_snapshot_equivalence_test.go`) is the snapshot-oracle uncovered-field
debt ledger. Today its class-M / validatorsSeenRoot poisoning path is covered by the
`validatorsSeenProbe` world but the A1/A2/A3 STAGES of the poisoning are not enumerated as named
debt. The PE ruling Q2 (`RULING-floorbox-R1.2-invariant-pins-2026-09-01.md`) traces the poisoning
in 8 steps; the three carrier stages are:

- **A1** — the spurious `validatorsSeen||id` ADD emitted by an unanchored class-A screen (steps 3-4).
- **A2** — the inflated `validatorsSeenRoot` digest the attacker commits as `b.StateRoot` (step 5).
- **A3** — class-M inheriting the inflated set via `RecomputeMatureNow(committedStateRoot)`, latching
  `everMature` early (steps 6-8).

Extend `probeUncovered` to NAME A1/A2/A3, pointing each to the driven gate that closes it
(`TestAdversarialRoot_ClassA_ForgedInEpochSet` / `_ForgedSlashed` for A1, the class-M gate for
A2/A3), so the poisoning-path coverage is enumerated, not silent. This makes the class-M debt a
named, discharged entry rather than an implicit one.
