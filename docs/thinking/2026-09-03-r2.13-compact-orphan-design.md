## 1. The mechanism, in one paragraph

A paid-serial guard entry can be appended, fsync'd, and reported durable, yet never be seen by a later
`Load` **because** `Disk.Compact` re-opens its append handle AFTER `os.Rename` (`guardstore.go:207-219`):
when that post-rename `OpenFile` fails, `Compact` returns the error but `d.f` still points at the
UNLINKED temp inode — writes and fsyncs through it succeed and go nowhere — and the sweep call site
discards the error (`delivery.go:559`). Masked today only because the ledger resets at the same restart
that would expose the hole; a live over-pay (a serial re-redeemed once per epoch since C-7) the moment
the ledger persists (FP-2) or is shared. This change addresses that **by opening the new append handle
on the temp file BEFORE the rename** (an fd on the temp inode stays valid across `rename(2)` and then
refers to the live path), so no fallible syscall runs between the rename and the handle swap — the
failure mode is removed, not detected. Evidence: the ruling's own measurement (§ "The one measurement
I ran"); G-CO-1 is that measurement inverted.

## 2. Options (from the ruling; recorded so the choice travels with the code)

| Option | Cost | Benefit | Call |
|---|---|---|---|
| open-before-rename (fd swap) | ~30 lines | removes the window; a pre-rename failure leaves the store UNCHANGED and `d.f` valid | **TAKE** |
| sticky `broken` on a failed post-rename open | store dead until restart | loud instead of silent | **TAKE as backstop only**, checked at the top of `Append` |
| fail-closed on any `Compact` error at the sweep | conflates a benign pre-rename failure (superset log, over-refuses) with a broken store; a self-inflicted liveness break under load | none | REFUSED (ruling §1 table) |
| fd swap without moving the open | same as today | none | REFUSED |

## 3. The shapes that are the Builder's

1. `Compact`: `write → tmp.Sync → tmp.Close → new := OpenFile(tmp, O_WRONLY|O_APPEND)` (fallible, PRE-rename;
   on failure return err with the store unchanged) `→ os.Rename → dir.Sync (best-effort) → old := d.f; d.f = new;
   return old.Close()`.
2. Port clause at `ports/ports.go` `PaidSerialStore.Compact`: after a `Compact` that returns an error, the
   store MUST either remain appendable with `Append` still durable-and-reachable, or MUST fail every subsequent
   `Append`; it MUST NOT return nil from an `Append` whose record a later `Load` cannot see.
3. Ledger side (`delivery.go:559`): stop discarding the error; branch on class — WARN for a benign compaction
   failure (the log is a superset; it only over-refuses), `ReasonGuardStore` (pay 0) only when the store reports
   itself BROKEN. Do not sweep the two into one.
4. Test seam per `docs/build-process.md` rule 8: `var openAppend = os.OpenFile` in the adapter, so G-CO-1 can
   force the failure. Note it as a source gate.
5. The ROADMAP FP-1 parenthetical is corrected in this PR (the "ruled safe / owes no gate / self-heals"
   reading is REFUTED on all three clauses — ruling §4); the false ROADMAP:548-549 text was already replaced
   in the definition program, so only the FP-1 line remains.

## 4. Gates (RED-first, `adapters/guardstore` + `core/credit`)

G-CO-1 forced post-rename open failure ⇒ `Compact` errors AND the next `Append` is either non-nil or visible
to a fresh `Load` (never nil-and-invisible). G-CO-2 a benign pre-rename failure does NOT refuse payouts (the
anti-over-correction gate, written BEFORE the ledger change). G-CO-3 a store that reports itself broken makes
every guarded redeem return `ReasonGuardStore` and pay 0.
