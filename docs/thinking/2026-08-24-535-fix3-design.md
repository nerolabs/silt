# #535 fix (3) design — the weak-subjectivity liveness-floor escape

**Date:** 2026-08-24. **Issue:** #535. **Status:** DESIGNED, not built — the
remaining layer of the certified recovery stack. **Rests on:** the research
certification `.../535-epoch-boundary-liveness-cliff-RESEARCH-CERTIFICATION-2026-08-23.md`
and the fix (2) refutation (`docs/thinking/2026-08-24-535-fix2-refuted-stack-is-4-plus-3.md`).

## Why fix (3) is the recovery (not fix (2))

The certified stack is **(4) + (3)**. Fix (4) (R-gate restore exemption, shipped
#541) heals the common case where departed members *return*. Fix (2) (automatic
boundary re-basing) was **refuted** — excluding possibly-honest lapsed weight
raises the Byzantine fraction and reopens I1 at field parameters
(`modelcheck_535_fix2_rebasing_test.go`). So the recovery for a **genuine
> ⅓-of-frozen-weight loss that does not return** is fix (3): an
operator-directed re-snapshot that carries the weak-subjectivity trust.

**The safety pivot:** a genuine > ⅓-honest-loss is *outside* the BFT liveness
model — no automatic protocol rule makes progress safe there (that is exactly
what the fix (2) refutation proves). Recovery therefore moves the trust to a
**human** who confirms the departure is a real outage (not a Byzantine attack)
and accepts the weak-subjectivity assumption — the same class of out-of-band
action `WSCheckpoint` already requires for long-range recovery. The protocol
never silently weakens its own quorum; a bled boundary STALLS (certified-correct)
until an operator deliberately invokes recovery.

## The mechanism

**Config (the operator directive):** `Config.LivenessRecoveryHeight uint64`
(default 0 = off), an epoch boundary height at which the mature-epoch validation
re-bases against the LIVE qualified bonded set instead of the frozen `epochSet`.
Consensus-critical genesis/coordination config, same discipline as
`WSCheckpoint` / `RegGateActivationHeight`. Daemon flag
`-liveness-recovery-height` with the WS caveat in the help text. **Socially
coordinated:** every honest operator MUST set the SAME height, or replicas
diverge — the operator's responsibility, the WS trust model (identical to
agreeing on a WSCheckpoint).

**The re-based set** at height `H == LivenessRecoveryHeight`: the live qualified
bonded set `{id : bonded[id] >= MinBond, !slashed[id]}` — the same computation
`rotateEpoch` uses for `next`. Deterministic, replica-identical (pure function of
committed state). The lapsed/offline members whose bonds have TTL-expired are
absent from `bonded`, so they drop out of the denominator; a member that
re-bonded via fix (4) is present.

**The three validation predicates must ALL be recovery-aware at `H`** (this is
the multi-touch care the build needs — the I1 surface):
1. `requireEpochWeightQuorum` — `total`/`support` sum the live-set weights (not
   `epochSet`) when validating the block at `H`.
2. `attesterQualified` — a live-qualified member may attest the `H` block even if
   it is not in the stale frozen `epochSet` (else a fix-(4)-rebonded member can't
   help).
3. `proposerQualified` — likewise for the `H` proposer.
   Cleanest encoding: a single `effectiveEpochSet(h)` that returns the live
   qualified set at `h == LivenessRecoveryHeight` (a boundary) else `c.epochSet`,
   consulted by all three. Thread `h` into the three predicates for the boundary
   block's validation only; every other height is unchanged.

**After the `H` block commits,** `rotateEpoch(H)` already snapshots the next
epoch against the live qualified set — so from `H+1` the chain runs normally on
the lighter set. The recovery is a one-boundary event.

**Operator visibility (I4/S5 — never silently fail):** when the head is stuck at
a boundary height (not advancing past `h % EpochBlocks == 0`), surface it —
`chain-status` gains a `stalled-at-boundary: h (live-qualified weight below the
frozen ⅔ bar — a liveness-floor recovery may be required; see
-liveness-recovery-height)` line, and the daemon logs it. This is how the
operator knows to invoke recovery. (The head-stuck state is already visible via
`chain-status` head height; this adds the diagnosis.)

## What the model-check must prove (the deterministic home)

Extend the #535 model-check with the recovery schedule:
1. **Recovery works:** with `LivenessRecoveryHeight = H` set, a boundary that is
   wedged under the full frozen set (>⅓ offline) COMMITS against the live set and
   rotates — the chain resumes. (The mirror of `modelcheck_535_boundary_wedge`'s
   stall, now recovered.)
2. **Safe default:** with `LivenessRecoveryHeight = 0` (or ≠ this boundary), the
   bled boundary STALLS — the re-base is NEVER automatic.
3. **Deterministic:** the live set at `H` is a pure function of committed state
   (replicas that set the same `H` re-base identically).
4. **Honest bound (what it does NOT prove):** the model-check CANNOT prove the
   operator's judgment is correct — if the operator invokes recovery when the
   loss is actually a Byzantine attack (not a real outage), the re-base can fork,
   exactly the fix (2) counterexample. That residual is the accepted
   weak-subjectivity trust, documented, identical to accepting a bad WSCheckpoint.
   The test asserts off-by-default + determinism + recovery-when-invoked; the
   trust anchor is the human, by design.

## Interim safety floor (already true today)

Even before fix (3) ships, a genuine > ⅓-honest-loss is **operator-recoverable**:
operators can coordinate a restart from a fresh `WSCheckpoint` / genesis against
the surviving set — the same weak-subjectivity action, more drastic. Fix (3) is
the smooth in-protocol version (one boundary, no restart). So the #535 class has
a recovery path today (fix (4) for returning members + a coordinated
WS-checkpoint restart for genuine loss); fix (3) is the ergonomic completion.
