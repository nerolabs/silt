## What was built, and the two catches the discipline made

**S1 + S2 at tier 2 (launch regime), `core/node/modelcheck_s1s2_test.go`** —
over the REAL node loop via held delivery: S1 parks the final round-0
precommit reply so a real commit quorum for X exists that only the proposer
could complete, then round-changes everyone; S2 additionally has the Byzantine
anchor (real node on the wire for its honest half) inject a crafted
round-change carrying a forged Y-lock (its own prepare as the "QC"), sent from
a probe endpoint with its real key — Byzantine behavior as INPUT, no code
knobs. Shared oracle: the contested height commits everywhere, same hash (X),
**CommitRound == 1**, no honest slash.

- **Catch 1 (anti-vacuity, the #303 discipline):** the first S2 run went green
  VACUOUSLY — the drain-designee's failed proposal consumed its pending regs
  (proposeBlock re-queues only un-embedded regs), the 3-sweeper round-change
  quorum fell to 2, no view-change fired, and the released reply completed a
  clean round-0 commit. The `CommitRound == 1` assertion caught it. Fix:
  refill pending regs before each sweep (production: registrants resubmit
  continuously). Lesson re-learned: assert the MECHANISM ran, not just the
  outcome.
- **Catch 2 (RED proof, recorded controlled revert):** the lock machinery is
  not test-toggleable, so RED was proven by a 2-hunk local revert — (i)
  `maybeAdvanceRound` lock carriage off, (ii) the prepare handler's defensive
  lock rule off. Both oracles then FAIL with "I1 VIOLATION: node 0 committed a
  different block at the contested height" — the lock-free view-change commits
  a fresh drain block at r1 while the prepared X is orphaned/completed at the
  proposer. Revert restored; diff shape and output in the commit message.

**Mature-regime faces, `core/chain/modelcheck_s1s2_mature_test.go`** — over
the real frozen weighted epoch (the B2 world): a sybil-packed,
head-count-rich/weight-poor prepare-QC is refused at the commit gate AND as a
round-change lock (S2's misreport in weight — the POL threshold IS the commit
threshold, §4); a lower-round signature never completes a higher-round
certificate (S1's face in weight). **Named residual:** the DYNAMIC node-level
mature S1/S2 (a live epoch network under held delivery) — no node-level
mature-epoch fixture exists yet; the locking code paths are regime-independent
and the weight predicate is pinned at chain level, but the dynamic run should
exist before the mature phase ships to the field. Not silent: recorded here
and in the PR body.

**The wedge oracle, `core/node/modelcheck_i4_liveness_test.go`** — imported
from branch `oracle/i4-liveness-wedge` (born RED at commit 3617b1d,

**I2 per-(h, r, phase) restart, `core/node/modelcheck_i2_rounds_test.go`** —
REFUSE (same-slot competitor refused after restart; blank-store control

## Order of checks in the sweeps (a modeling note)

The oracles call the sweep body (`maybeProposeBondDrain` + `maybeAdvanceRound`)
directly — `chainSyncTick`'s timer never fires under the frozen driver clock.
That is the production cadence minus the wall-clock, which is the point
(B2/#3: round advance is sweep-counted, never timed).
