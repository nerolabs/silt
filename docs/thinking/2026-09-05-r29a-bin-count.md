  singleton cells 86% of occupied at R = 25, 35% at R = 400; exposed-identity count 33 → 14

  the bin count is the ONLY lever that acts on that exposure; merging and rounding REFUTED at

- `core/credit/bbootstrap.go:770-789` at `d861a3e`: the bin index is `4·e + q` with `q` from

**Options weighed:**
- **(A) Set the constant to 1 and leave the quarter-octave machinery in place** — smallest diff;
  leaves three dead constants and a dead `switch` under a build tag CI compiles but nothing
  exercises. Dead instrument code is exactly the "mechanism that outlives its reason" the PE
  called out on the bond stamp (#739/#740). Rejected.
- **(B) Set the constant to 1, delete the quarter machinery, keep `BinsPerOctave` as a
  published field** — the bin function becomes `bits.Len64(b) − 1`, clamped. The wire stays
  self-describing (`binsPerOctave`, `byteBins`, `byteBinRule`) so a third party can read a
  histogram from either era without ambiguity. **Chosen.**
- **(C) Make the axis runtime-configurable** — a knob on a privacy lever, and the owner just
  pinned the value. Foreclosed by the ratification. Rejected.

**Decision + rationale:** (B). Every site that named the old resolution changes with it, found
by grep, not memory: the constants block and its rationale (rewritten around the two facts
that decided the value, so the payload argument that chose 4 cannot re-decide it), the struct
comments, `BBootstrapByteBinRule`, the flag help text, and four test files. The BB-5 payload
ceiling drops 32 KiB → 8 KiB (328 counters). The BB-16 fixture's fetch steps become doublings
so each fetch crosses exactly one edge on the coarser axis; its control arm needs ≥ 4
single-identity steps and 1 MiB increments would have crossed only three. The node-level test
had two bin indices hard-coded for the quarter axis (250 B → 31, 1,000 B → 39); they are
7 and 9 now, with the closed form in the comment.

**Gate.** `TestR29aByteBinMatchesTheClosedForm` now pins the RATIFIED resolution by name:
`BBootstrapBinsPerOctave == 1`, the counter count 328, the wire rule string, and the exact
power-of-two edges across the whole axis. A finer axis fails with a message naming G-BB-23.

**What would change my mind:** a ratification recorded in `docs/decisions.md` moving the value.
Nothing else — the residual disclosure (`R-BB-SINGLETON-CELL`, reduced not closed) is in the
code comment and stays open.
