# R4.3a — the DHT domain-0 exemption and the single `-domain` flag

**Date:** 2026-09-03 · **Seat:** PLANNER (deliberation) → TESTER (gates) → BUILDER (fix) · **Status:** BUILT (PR #715); PE MERGE-WITH-CONDITIONS, conditions landed

**Binding input:** the R4.2 direction certification
`silt-reviews/research/research-outcome/R4.2-A-axis-operator-diversity-DIRECTION-RESEARCH-CERTIFICATION-2026-09-03.md`
§3 (finding (ii) CERTIFIED: the domain-0 exemption; the further defect: one `-domain` flag serving two
masters, a literal build-immutable-#3 instance) and its disposition: *"routing-only, changes no validity
predicate, can ship inside the RC window: split the two labels, and make an unknown DHT domain count

do). It requires no era, no cert beyond this line."* Not research-gated.

---

## 1. The mechanism, in one paragraph

A key-surround adversary defeats the H5-B eclipse cap for free **because** `domainSaturated`
(`core/dht/table.go:39-46`) returns "never capped" for a peer whose domain is 0, and the domain is a
free, unverified self-declaration off the wire (`core/node/node.go:1494-1498`): omit `-domain` and every
Sybil sits in the exempt bucket; the same label also feeds the C2 concentration metric, whose default
for "unset" must be the opposite (independent). This change addresses the exemption **by counting every
unknown-domain peer against one shared "unknown" bucket under the same per-domain cap** — unknown ⇒
capped, the conservative default the DHT layer wants — and leaves the metric's label untouched.

## 2. Options

| Option | Cost | Benefit | Call |
|---|---|---|---|
| (a) unknown ⇒ counted in a shared bucket under `perDomainCap` | ~10 lines in `table.go`; a placement-preference note (`preferFreshDomain` stays as is — it is anti-affinity, not the eclipse veto) | closes the free "omit `-domain`" evasion; no wire, no port, no era | **TAKE now (R4.3a)** |
| (b) key the DHT cap on the OBSERVED remote address (/24), the geth / Bitcoin Core form | a ports change (the transport must surface the remote address per peer; the sim has no addresses, so a sim-side domain oracle is needed); table keying by address bucket | closes BOTH evasions (omit, and N random labels); retires `-domain` from the DHT entirely, which IS the immutable-#3 split | **FILE as R4.3b** (Builder + crypto-specialist advisory on the bucket width; not research-gated per the cert) |
| split the label now (a second `-dht-domain` flag + additive gossip field) | a gossip wire field that (b) deletes again | the literal "split the two labels" | REFUSED as churn: (b) achieves the split by removing the DHT's use of the declared label; a second declared label is the same free declaration under a new name |

**Scope note for the owner:** the certification says "fix both". This session ships (a) and the metric
print; the flag split is delivered by (b), not by a second declared label. If the owner wants the literal
second label before (b), it is a one-line flag plus an additive gossip field — say so.

## 4. Gates (RED-first, `core/dht` + `core/node`)

G-D0-1 a bucket already holding `perDomainCap` unknown-domain peers refuses a further unknown-domain
peer (RED today: never capped). G-D0-2 an at-cap bucket still admits a peer from a KNOWN, distinct
domain (the diversity property survives). G-D0-3 with the cap off (`perDomainCap == 0`) nothing changes
(legacy). G-D0-4 the S5 status line carries the two domain metrics (e2e or `cmd/silt` unit).

## 5. As built, and what the PE measured (2026-09-03)

- PE ruling: `silt-reviews/principle-engineer/RULING-R4.3a-dht-domain0-cap-adb31e1-2026-09-03.md`,
  MERGE-WITH-CONDITIONS; both conditions (the two flag help texts; the `diverseNear` comment) landed.
- **The measured price, disclosed:** in a swarm where nobody sets `-domain`, honest routing-table density
  roughly halves (N=30: average 17.1 → 8.9 entries, minimum 12 → 6; with K=8 and cap 2 the unknown bucket
  is 25% of every k-bucket). Honest liveness held in the PE's sims (10/10 lookups at N=4/8/30; bootstrap
  converges; consensus never reads the table). Discoverability against 10 undeclared eclipsers went
  0/6 → 4/6 (adversary incumbent) and 3/6 → 6/6 (adversary late).
- **The residual, named:** a LABELLED adversary (N random `-domain` labels) is unaffected — 10 labelled
  eclipser incumbents leave 1/6 discoverable. That is R4.3b's job and it must not slip past the RC gate.
- **A coupling the R4.3b line now carries:** observed-address keying collides with the relay tier — NATed
  ponies behind one `-relay-via` present the relay's address and would be capped together (immutable
  #4/#5 pressure on the tier the economy needs). R4.3b must key on the observed address of DIRECT
  connections and treat relayed peers separately.
- `peerDomains` evicts at random at 4096 entries; an evicted declared peer now reads as "unknown ⇒
  capped" instead of "unknown ⇒ exempt" — the conservative direction, noted.
- G-D0-4 (the S5 status-line gate promised in §4) is NOT a separate test here: the PE verified all four
  consumers of the C2 line (`integration/sybil/run.sh`, `integration/cloudtest/scenarios.sh`) survive the
  inserted segment; the line joins the S5 registry (PR #716) once both merge.
