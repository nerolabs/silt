## 1. The mechanism, in one paragraph

The relay lane minted **because** nothing bound a PayWord chain to a payment the fetcher had actually
made: `RelayOpen.Funding` is a bare fetcher-set integer, and settlement debited a phantom ephemeral on the
relay's own ledger (R0.7; interim shipped in PR #718: pays 0). This change addresses that **by making the
chain root a commitment under a relay-issued, blind-signed prepayment credential** the fetcher withdraws
privately (`ChargePublish` on the paying ledger, the same bilateral shape the delivery lane runs), which the
relay verifies at open and spends once at settlement; `RedeemRelayCredit` then pays `min(count, face)` only
against a spent anchor, so `settled(R) ≤ Σ face(spent anchors)` holds by construction and a colluding
fetcher+relay pair rebuys its own fee at a strict loss (the B3 argument).

## 5. Build record (Builder, 2026-09-04)

Built as certified, in the advisory's nine-step file order; nothing substituted. The choices the
cert left to the Builder, and the fixture corrections, so they travel with the code:

- **Encodings adopted from the Tester's gates:** `M` widths `uint32BE(S) ‖ uint32BE(k)`; `RelayOpen`
  cbor keys 4/5/6 (`omitempty`, so a v1 payload round-trips) and `Anchor{1: Serial, 2: Sig}`. Two
  width pins were ADDED so `M` is injective without length prefixes: the root must be exactly one
  hash and a serial exactly `blindtoken.SerialSize` (`errRelayBadRoot` / `errRelayAnchorMalformed`,
  both before any crypto).
- **The guard is the R0.4b paid-serial map, shared, not a twin.** `SpendRelayAnchors` reuses
  `paidKey`, the epoch watermark, `sweepIfEpochAdvanced`, a k-slot `reservePaidSerials` (the 1-slot
  form now calls it) and `addPaidSerial` with the same `PaidSerialStore`. One consequence in the safe
  direction is written into `relayanchor.go`: a serial blinded in BOTH domains funds one lane only.
- **`SpendRelayAnchors` reasons:** `ReasonAlreadyPaid` / `ReasonGuardFull` / `ReasonGuardUnloaded` /
  `ReasonGuardStore` / `ReasonBackdated` / `ReasonNoFee` shared with the delivery lane; new
  `ReasonNoAnchor`, `ReasonAnchorMalformed`, `ReasonAnchorFuture`. The node maps AlreadyPaid →
  `errRelayAnchorSpent`, GuardFull → `errRelayGuardFull`, else `errRelayGuardRefused: <reason>`.
- **`withdrawBlind`:** the demand withdrawal generalised by (blind, unblind) so `AcquireRelayAnchors`
  is the same wire path as a demand token with the relay-domain primitives. The issuer side is
  untouched. On a mid-run failure `done` returns the anchors already bought WITH the error, so paid-for
  value is never dropped.
- **The relay's own account is registered in the fixtures** (`newAnchorCluster`, `relayPairForTest`,
  the restart relays): on a live daemon the first economy read registers it long before a settle;
  without it the settle's `acct(relay)` would apply the faucet grant and every ledger-total oracle
  would read that grant as Δ. A fixture fact, not a rule change.
- **Two Tester assertions corrected** (each a false premise about the fixture, not about the
  property): T-3 `cap_refuses_never_evicts` assumed a k=6 batch refusal leaves the table exactly
  full (65,536 mod 6 = 4 free slots remain) — it now tops up one anchor at a time, then asserts the
  k=1 refusal; T-10 assumed `OpenRelaySession` inserts into the session table (only
  `handleRelayOpen` does) — it now asserts the count is unchanged by the refused open.
- **Existing relay tests ported, one line per open**, via `r214_relay_fixtures_test.go` (cached RSA
  keys; `commitSelfDemandKey`; `mintAnchorsFor`; `openAnchored`). `TestRelayOpenFloodStaysBounded` is
  re-specified: a FREE flood now admits nothing (priced admission — the property RT-RELAY-3 was owed);
  the cap and the sweep are pinned by direct insertion because 4,096 anchored opens would cost the
