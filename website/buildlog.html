How silt was built

The design choices, the mistakes, and what we learned, newest first. The changelog says what changed; this says why.

A floor box has to catch up

November 2026

A floor box checks each new block against proofs that other nodes serve. On a slow test machine, a box asked for the state of a block its providers had already moved past, and stalled for good. Our first fix kept recent state only once a box had asked for it, and the same test failed again: a box's first request names the checkpoint its operator gave it, which the network may already have left behind. Now every node keeps a cheap snapshot of its last eight blocks and does the expensive work only when a box asks. The lesson: a mechanism that waits for its user to show up will always miss that user's first request.

Simulated people found what the tests didn't

November 2026

We built a script that runs a whole network on one machine, with simulated people publishing and fetching, so we could watch it in the web UI. Within minutes it showed that publishing through an ordinary storage node failed, in three separate ways, each of which the unit tests passed. The simulated users are now a check that runs on every change.

One bug in four costumes

August 2026

Four consensus failures looked unrelated in the field: a chain that switched between committed histories, a handoff that cheap identities could vote their way into, honest validators punished for a race, and a quorum counted over the wrong set. They were one bug. Each time, two quorums that should have shared an honest member did not. That is the oldest safety rule in Byzantine consensus, and it is now written down as five invariants that every consensus change has to name.

Finishing the chain we had

August 2026

Under real wide-area latency, the chain sometimes rewrote blocks it had already committed. The answer was not a new mechanism. The chain was already nearly a bond-weighted Byzantine-fault-tolerant chain, and we finished it: a block committed by a quorum is final and is never reverted. The local simulation had passed throughout, because it only ever tested a chain that had already settled.

The wide-area rabbit hole

August 2026

For two and a half weeks one bug, a fresh three-region chain that would not commit its first block, absorbed the project. It was re-diagnosed five times, and each new theory cost a paid cloud run. The fix came only when we stopped, instrumented the code and reproduced the bug on a laptop. When a log goes quiet under a pile of cloud runs, the work is stuck in a loop.

Starving the dial-storm

August 2026

When a node leaves, the rest of the network keeps a note that it holds certain files, and keeps dialing it. Enough of those notes and the network spends its time calling the dead. Each note now lives on a lease that its holder must keep renewing, and nodes stop passing on notes they know are stale. Before writing any code we read the existing code, and found that the first suspect had already been fixed weeks earlier.

Meeting across networks without becoming the network

July 2026

Two nodes on different home networks could neither find each other nor connect. We split the problem in two: learning that a peer exists, and getting a socket through two routers. Where a relay is needed, any node can be one, and the project runs none. A relay only joins two byte streams; the nodes run their own encrypted handshake through it, so a relay cannot read what it carries.

The placement spectrum

July 2026

silt first placed every piece of a file independently, by its own hash. That spreads data perfectly, but a read costs one lookup per piece, and nothing stops two pieces landing in one failure domain. We now place by column: one piece position across the whole file, found in a single lookup, and spread so that losing a node, a rack or a provider costs at most one piece per stripe.

One process, a real product from day one

July 2026

Instead of starting with a fleet of servers, we built the whole network inside one process first, with a simulated clock and network. The core logic (chunking, encryption, erasure coding, routing and repair) imports no networking, no filesystem and no clock, and a test fails the build if it ever does. When the network moved onto real machines, only the adapters changed.
