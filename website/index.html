Content-blind by architecture · no coin, no token · experimental

The infrastructure is not the content.

Silt is peer-to-peer storage. A file is encrypted on your machine, split into pieces with redundancy, and spread across other people's nodes; the link you get is both its address and its key. A node cannot read what it holds; it was built to be unable to, and the network repairs a file as nodes come and go. A publish names no author. There is no coin, no token and nothing to buy. Meaning lives elsewhere, with whoever holds the keys.

Surface · what it is
Content-addressed

A file's name is its hash

Every fragment is named by the SHA-256 of its bytes. Verification is intrinsic — you never have to trust a host, because a chunk that doesn't hash to its name is rejected on sight. Trust is replaced by arithmetic.

Erasure-coded

Any 10 of 16 rebuild the whole

Files are Reed-Solomon coded into stripes: lose any six fragments of sixteen and the file reconstructs, bit-perfect. A repair loop watches for decay and rebuilds what's missing. Losing machines degrades redundancy, not the file.

Encrypted at every level

Ciphertext describing ciphertext

Chunks are encrypted. The manifest that reassembles them is itself encrypted. The public name is thirty-two bytes that reveal nothing. To open a file you need a link — a key that travels between people, never through the network.

Governed by earned standing

A validator's seat is earned, not bought

The registry is a chain the validators keep together. A file is registered when a quorum of validators commits it, and a validator earns its seat by proving it holds real storage — an identity-bound proof-of-space-time bond, challenged and re-proved, that costs real disk. Nothing is bought. Anyone can publish: each publish carries a blind token signed by the validators, so the record names no one and cannot be linked to who made it.

Reaches across NATs

Two home routers still connect

Nodes behind ordinary home routers find each other and move data — a content-blind relay bridges them, and where the network allows it they upgrade to a direct, hole-punched link. No public IP or port-forwarding required.

Deposition · the path of a file

From your disk to the swarm, and back again.

A

Chunk

The file is split into fixed-size fragments, each framed so it rejoins exactly.

B

Encrypt

Every fragment is sealed. Identical data can dedupe; secret data stays unguessable.

C

Erasure-code

Fragments are grouped into stripes with parity, so any k of n reconstruct.

D

Scatter

Shards are placed on the nodes nearest each hash, spread so one death costs little.

E

Register

The file's root is committed to the chain. Retrieval reverses every step, verifying all.

Retrieval is the mirror image: resolve who holds the shards, fetch them, verify every hash, rebuild what's missing from parity, decrypt with the key in your link, reassemble.

Bedrock · carry the network

Pledge storage. Earn standing. Hold the network up.

A public node contributes a slice of disk and bandwidth and serves encrypted shards to whoever asks. Pledge an identity-bound storage bond and survive its spot-check audits, and your standing rises — until the network trusts you to help write its history. There is no sign-up. Generating a keypair is joining.

Read the operator guide
  • Pledge what you mean. Start a node with a fixed budget — silt daemon -capacity 2G. The network continuously knows its own total size.
  • Serve, don't hoard. Serving earns credit: an accounting unit each node keeps, earned by serving bytes and spent to keep files alive. It is not a currency — it can't be bought, sold or taken out of silt. A validator's seat comes from its storage bond, not from credit.
  • Prove you hold it. A validator's storage bond is challenged with a fresh nonce, again and again. Drop the data and it fails the challenge and loses its seat.
  • Never trust, always verify. Every shard is hash-checked on receipt; every block re-validated by every replica. Lying wastes a round-trip, never corrupts data.
Strata · the registry chain

History by earned agreement, not by mining.

The list of what the network hosts is an append-only chain the operators keep together. A block commits only when a quorum of reputable validators sign it — no single node decides, and no electricity is burned. Because a node's identity is its key, a bad reputation can't be shed without becoming a stranger again.

Get Silt · build it from source
Experimental — build from source. silt has no binary release and has not been audited. Don't keep your only copy of anything in it, and don't use it where being identified could put you at risk: it does not hide your IP address from the nodes you talk to. It has been through one blind red team; every finding is fixed, and a second, independent red team runs before release. Please read the threat model — finding a way to break a promise it makes is exactly the review we most want.

Who builds silt. AE Laboratories maintains silt and makes its decisions. It is built with Claude, Anthropic's AI model, which writes most of the code and the tests. The source is Apache-2.0 on GitHub.

Run the client. It serves while it fetches.

One self-contained binary — no runtime, no install. The desktop client consumes and contributes in the same process: downloading and helping carry the network are the same act. It's Go with no cgo, so building it yourself takes one command:

# clone and build for your machine…
git clone https://github.com/nerolabs/silt && cd silt
go build -o silt ./cmd/silt   &&   ./silt client

There are no binary releases: silt is experimental, and you build it from source. You need Go 1.26.

▶ Want to see it work? Build your own Silt test network on your own computer — one script runs a whole network on your machine, with validators, storage nodes, floor boxes and simulated people publishing and fetching, and a web page to watch it.

The line · what Silt is and is not

Silt carries bytes. It does not know, or care, what they mean.

What Silt is

Neutral infrastructure. It stores, serves, verifies, heals, and proves that encrypted fragments are still here — the way a road moves traffic and a wire moves current: faithfully, without opinion about the cargo.

What Silt is not

It is not a place to browse, search, or discover what exists. It attaches no names, no descriptions, no meaning to anything. Resolving a file's identity into what it actually is belongs to a separate layer, built by others — the way DNS sits above IP. Silt answers a smaller, honest question: is the data still here?

Can it be misused?

Like any storage, yes. silt removes content by its hash, on the nodes whose operators choose to: each operator keeps their own denylist and follows the takedown curators they trust, and every on-chain takedown is recorded and names its curator. No one can remove a file from every node at once, and nothing acts on a person. To report abuse, write to abuse@silthq.com; the operator guide says what operators can do.
